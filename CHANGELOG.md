# Changelog

All notable changes to the `ak-bench` package are documented here.
Versions follow the `MAJOR.MINOR.PATCH` scheme; a new entry is added for every
release tagged as `v<version>`.

## [Unreleased]

### Security
The dashboard was written to be read on the machine that started it and is now deployable elsewhere; these are the consequences of taking that seriously.

- **The dashboard asks who is asking.** `bench_ui/security.py` and a small ASGI middleware put every route behind HTTP Basic, with two roles: `viewer` and `judge`. Authentication engages by itself unless the bind address is loopback, and an address the app cannot classify counts as exposed rather than private. Configured to authenticate with nobody in it, the command line refuses to start and a served app answers 503 — a module that raises on import reports nothing at all, which matters because uvicorn loads this one by import string. `/docs`, `/redoc` and `/openapi.json` are off. See `AKBENCH_UI_*` in the README.
- **A task's hidden tests and its planted defect are a separate privilege from its scoreboard.** Both were rendered and downloadable by anyone who could reach the port — the file tree, the descriptor's `mutation` section, and `GET /api/tasks/{uid}/download.zip` — which is the answer key of the benchmark. A `viewer` now gets the runs, the scores and the task prose; the descriptor they do see is reparsed with those two keys removed, and the archive is packed without those two kinds.
- **PostgreSQL is published on loopback, and the password has no default.** `scripts/run-postgres.sh` took `-p "${PORT}:5432"`, which binds every interface on the machine even while `AKBENCH_PG_HOST=127.0.0.1` read as "this box only"; publishing and connecting addresses are now separate variables. The bootstrap superuser's password was `akbench_local` in the code, the config and the example env at once, and connecting as that superuser made SQL access host access (`COPY … PROGRAM`, `pg_read_file`). There is no default to fall back on, a well-known value is refused, the password is a `SecretStr` so `config show --json` no longer prints it, and `AKBENCH_PG_APP_USER` provisions a role holding only the privileges AK-Bench uses. `env` and `start` no longer print the secret.
- **A recorded artifact path is read only inside directories the installation named.** `GET /api/artifacts/…` opened the path from the database row as given, so one writable row read any file the dashboard's own user could read — `.env` among them. Nothing was configured to name those directories before, so now there is `AKBENCH_UI_ARTIFACT_ROOTS`.
- **A page behind credentials is not cached, and every response carries security headers**: `Content-Security-Policy` (same-origin, which is also why Chart.js is vendored instead of loaded from a CDN a third party could substitute), `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`.
- **Two stored values stopped reaching `innerHTML` unescaped** — `run.status`, and the verdict-derived badge class, both free `VARCHAR(32)` columns. The class now comes from a fixed list, the way the server templates already chose it.
- **A request cannot ask for the whole database.** `limit` is bounded (and a negative one no longer means "everything"), the whole history is collected once per few seconds instead of several times per page, and the route handlers are synchronous so a database call runs on a worker thread instead of blocking the event loop: eight concurrent dashboards used to take 37 s in a strictly serial queue, one behind the other.
- **Namespace and `search_path` handling**: `validate_namespace` also runs in `create_namespace` and `_quote_schema` (whose docstring promised validation it did not have — it lived only in one CLI caller), the quote is escaped by doubling rather than assembled, and a namespace is checked before it is embedded in the libpq `options` startup parameter, where a space would append further `-c` settings to the session.
- **Smaller things**: a database error's text (host, port, user) no longer renders on every page and in a footer tooltip; `dotenv_path` is not sent to the browser; an engine-construction error names its URL with the password redacted; a JUnit report declaring a `DOCTYPE` or `ENTITY` is refused rather than expanded; a `LIKE` lookup escapes its wildcards; the run modal's `data-sort-value` attributes are escaped.
- **A freshly initialised database opens.** The dashboard ledger formatted four counters with `f"{value:,}"`, and a history in which no run reported tokens has `None` there, so an installation with nothing recorded answered its first visitor with a server error.

### Added
- **The model charts say which models the runtime's log confirmed.** A model a run only asked for is weaker evidence than one the instance's log named it serving, so each model now carries how many of its runs were verified, shown beside its name on the charts, with a one-line note under them that says how much of the comparison rests on that kind of confirmation.
- **A dark and a light palette, switchable from the navigation.** The theme is one swap of the variables the pages already read, so the markup and the component rules are untouched and the choice is remembered across pages. It is applied before the sheet paints, so a page never opens in the wrong palette, and the charts redraw when it changes because a canvas cannot follow a variable.
- **The runs table is driven from the keyboard.** Up and down move a cursor between the runs on screen, Enter opens the run under it, and `/` drops straight into the filter search. The row the cursor rests on is marked, so a reader moving with the arrow keys can see where Enter will land; the keys belong to whatever is being typed into, so the cursor stays out of the way of an input, a select and the run inspector.
- **The runs explorer copies its filtered rows out as CSV or Markdown.** Two buttons in the runs panel header take the rows the current filters match — refetched from the API, so a filter that has not repainted cannot export a stale answer — into the clipboard as a CSV for a notebook or a Markdown table for a message. The export carries the numbers the API holds (raw score, seconds, tokens), not the strings the page prettifies, and skips the columns that only drive the page (the comparison checkbox, the inspect button).
- **The UI shows what a run cost in calls, not only in tokens.** Every table that lists runs or configurations — the dashboard leaderboard and recent runs, the runs explorer, the task and experiment pages — carries a tool-calls column, with the raw number beside it so it sorts. The dashboard charts compare the models against each other on the same measures (success rate and score, duration and tokens) instead of one model against itself across metrics.
- **The dashboard opens with the overall picture.** Experiments, runs, evaluated, success rate, tasks, total and mean time, input/generated/total tokens and tool calls in one block, cost shown as "not recorded" until the history carries it.
- **A task's code is downloadable.** `GET /api/tasks/{uid}/download.zip` packs every recorded file under its kind, named `{task-id}__{version}.zip`.
- **The task page charts score per configuration** — one line per configuration over the task's runs in the order they started — and folds its long prose (the description) and its code tree away, so the definition is the first thing read.
- **The analytics explorer spins while it loads.** Every chart shows a loader until its data has been drawn, so an empty chart is not mistaken for a broken one.

### Changed
- **The dashboard's recent-runs and leaderboard tables repeat the run's repetition number** beside the other run columns, and every table that lists runs shows it.
- **Code viewers offer a copy button beside close** in the task code viewer and the run modal, so the text shown can be taken without selecting it.
- **YAML in the UI is coloured.** The recorded descriptors (task, experiment, agent, runtime) and the task's `description.md` get a light syntax highlight for keys, values and comments.
- **The runs explorer shows which tests passed and which failed in a run.** The inspect modal lists the evaluator's per-test results — green for a pass, red for a fail — when the run recorded them, alongside the passed/failed/total summary.
- **Numeric table columns sort both ways.** A cell's sort value is its own text, or the text it shows when it has none; a cell that opens with whitespace and nests its number in a span used to sort on nothing, which is why success rate, mean score and the against-baseline columns never moved. The against-baseline column now sorts on the success-rate difference it describes.
- **The runs explorer keeps its two-run comparison budget visible.** Selecting two runs dims the rest and disables their checkboxes, and the state survives filtering; the run diff opens on two runs chosen from lists of the same runs.

- **A task's code is recorded in the history and browsable in the UI.** `task_files` stores the repository a task is worked in, its hidden and public tests and its mutation patch, one row per file with a size and a `sha256` digest (migration `0010`); binary files and anything over 256 KB are left out rather than stored empty. The task page shows the code as an expandable directory tree grouped by kind, and clicking a file reads its text from `GET /api/tasks/{uid}/files` and `GET /api/tasks/{uid}/files/{path}`. `scripts/update_task_info.py` backfills the files of an existing history from the dataset on disk.
- **Agents and runtimes are first-class rows, filterable in the UI.** `agents` and `runtimes` keep every version a run was made of, keyed by the id the run already recorded, each with the descriptor file it declared (migration `0009`). New `/agents`, `/agents/{id}`, `/runtimes` and `/runtimes/{id}` pages show the descriptor as written — capabilities, controllable configuration, execution modes, endpoints — and the runs explorer filters by agent and by runtime.
- **An experiment carries its own descriptor.** `experiments.experiment_yaml` is the file the experiment was planned from, and its page shows a configuration panel read from that file plus the raw YAML, so an experiment explains itself without its checkout.
- **Every table sorts by clicking its column header.** First click ascending, second descending, a double click restores the page's own order; formatted cells (`1m 30s`, `1.2 MB`) sort by the value they show, and a table rendered after load arms itself through `window.akbenchSortTables()`.
- **Task content is recorded in the history and shown in the UI.** Every task row now stores what the task asks — the title, the one-line description, the full `task.yaml` descriptor and the task's `description.md` (migration `0008`). The UI answers a task page from the history alone: the task catalog shows titles, descriptions, authors and timeouts, and the task detail shows the definition with constraints, setup, mutation and repository, the full scope of work, and the recorded descriptor. When a task was recorded before its content was stored, the dataset on disk fills the gap and the page says the definition came from there.
- **`scripts/update_task_info.py` backfills an existing history** with the task content from the dataset on disk (migrating the schema to head first), for the PostgreSQL the project is already using.
- **The UI footer links [radlab.dev](https://radlab.dev) and [llm-router.cloud](https://llm-router.cloud/).**

### Changed
- **PostgreSQL is now the default database.** Recorded benchmarks go to PostgreSQL instead of the SQLite file, so a project has one shared, server-backed history. SQLite stays available as an explicit fallback for a laptop without a server.
- **A project `.env` file is read automatically.** The same `AKBENCH_PG_*` connection names `scripts/run-postgres.sh` uses now configure the engine; an exported variable beats the file, and `AKBENCH__DATABASE__*` still overrides both. The connection URL is redacted (password hidden) everywhere it is displayed, in `akbench config show` and in the UI footer.
- **`akbench migrate` imports a SQLite history into PostgreSQL, one namespace per file.** Several working directories share one server; each import lands in its own schema (read back with `AKBENCH__DATABASE__POSTGRES__NAMESPACE`), children after parents, every table counted on both sides, and a difference is an error. The import surfaced a real defect: `config_hash` was declared 64 characters while the code has always written `sha256:<64 hex>` (71) — SQLite never enforced the length, PostgreSQL does. The column is now what the code writes (migration `0007`).

## [0.1.0] - 2026-11-05

### Added
- **CLI and configuration.** A `typer`-based CLI (`src/akbench/cli/`) with `akbench init`, `doctor`, `config`, dataset, experiment and run commands; YAML configuration loaded with Pydantic plus an ENV layer where the environment allowlist treats secrets as presence-only, so a key's value never enters a descriptor (`src/akbench/config/`, `docs/CLI.md`).
- **Descriptor system.** Eight descriptor kinds — agent, runtime, plugin, dimension, model, category, evaluator, metric — each versioned and digest-pinned in a registry, so a recorded run pins exactly the descriptors it ran under (`src/akbench/descriptors/`, `docs/DESCRIPTOR_SYSTEM.md`, shipped descriptors under `descriptors/`).
- **Datasets and tasks.** Task descriptors, dataset validation, git-based repeatable workspaces, mutation verification of task sources and hidden tests that an agent never sees (`src/akbench/datasets/`, `docs/DATASETS.md`, `datasets/` with twelve task repositories and the shipped task sets, including the very-hard implement and bugfix tasks).
- **Agent adapter framework.** A capability contract, a registry, and the Codex CLI adapter with capability gating and contract tests, so a new agent is a module, not a fork (`src/akbench/agents/`, `docs/AGENT_ADAPTERS.md`, `docs/AGENT_INTEGRATION.md`).
- **Runtime manager.** Execution modes — direct, runtime, router — managed versus external lifecycles, an LLM Router adapter, the configuration triad, and a managed instance launched per run with its own environment, port ownership, and the instance log kept as a run artifact; the requested model is verified against the models the instance's own log attributes requests to (`served_models`, `routing_decisions`, `received_models`) with statuses `verified`/`unverified`/`mismatch`/`unsupported`/`not_configured`/`runtime_error` (`src/akbench/runtime/`, `src/akbench/runtime/llm_router.py`, `docs/RUNTIME_MANAGER.md`, `docs/ROUTER_INTEGRATION.md`).
- **Shipped runtimes and experiments.** A managed `llm-router-ak-bench` runtime (self-start) and a shared `llm-router-external` runtime, the `agentic_knowledge` and `agentic_routing_codex` plugin descriptors, and eight experiment configs: `full-matrix`, `knowledge-on-off`, `knowledge-replay`, `llm-router-external-fast`, `llm-router-selfhost-fast`, `model-comparison`, `router-config-comparison`, `wordcount-direct-sanity`.
- **Evaluator engine.** Pytest-based and command-based evaluators, isolation of hidden tests from the agent's workspace, and verdicts per run (`src/akbench/evaluators/`, `docs/EVALUATORS.md`).
- **Run orchestrator.** A lifecycle state machine (`pending` to `completed`, with terminal `failed`, `timeout`, `cancelled`, `infrastructure_error`, `invalid_configuration`, `evaluation_error`), per-run isolation, retries, and run records; a blocking run reports where it spends its time, and a run can report its transitions to an observer (`src/akbench/orchestration/`, `docs/RUN_ORCHESTRATOR.md`).
- **Experiments and planning.** An experiment descriptor, matrix strategies, validation that refuses — rather than degrades — a plan it cannot measure, routing of factors to their destination by a dimension's `source`, and a binding of a factor combination to the environment its runtime starts with (`src/akbench/experiments/`, `docs/EXPERIMENTS.md`).
- **Plugin observability.** A plugin adapter that reads plugin state only from an allowlisted environment and only from the environment the run itself launched, an `enabled_when` toggle, and verification statuses; a run reports only the plugins it configured (`src/akbench/plugins/`, `docs/PLUGINS.md`).
- **Knowledge replay.** Memory experiments with learning/fresh arms and a readiness gate (`src/akbench/knowledge/`, `docs/KNOWLEDGE_REPLAY.md`).
- **Storage and metrics.** SQLite with Alembic migrations, a history of repositories and tasks, artifacts, a reproducibility manifest with digests, aggregates, and baseline deltas (`src/akbench/storage/`, `src/akbench/metrics/`, `docs/STORAGE.md`, `docs/METRICS.md`, `docs/REPRODUCIBILITY.md`).
- **Reporting.** A static HTML report: a dashboard with the configuration ranking — one row per configuration (factor values + agent + runtime) pooling all of its runs, mean-per-run tokens and tool calls, places shared across experiments — plus experiment, task, agent, runtime, plugin and model pages, a "Not verified" table, and a `docs/` subpage rendering the project's own markdown with a styled menu (`src/akbench/reporting/`, `docs/REPORTING.md`).
- **Export.** JSON/CSV/HTML export with secret screening so an export never carries a credential (`src/akbench/export/`, `docs/EXPORT.md`).
- **Documentation.** `README.md` with a step-by-step guide to how AK-Bench reads a configuration, and one doc per subsystem under `docs/` (descriptor system, datasets, agent adapters, runtime manager, evaluators, run orchestrator, experiments, plugins, knowledge replay, storage, metrics, reporting, export, reproducibility, development, CLI).
