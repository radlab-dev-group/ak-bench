# Glossary

Terms as this repository uses them. Where a term has a section in `SPEC.md`
the section is given; the spec wins over this page.

**Action** — one entry in a schedule's `actions` list: a tick and a kind
(`partition`, `heal`, `isolate`, `block`, `unblock`, `crash`, `restart`,
`skew`, `network`, `propose`, `workload`). SPEC 9.2.

**Apply** — feeding a committed entry to the state machine. Traced as
`apply`; part of the digest. SPEC 4.4.

**Ballot** — one node's real `RequestVoteResponse` grant in one term. A node
holds one per term and its own candidacy spends it, so a candidate denies a
rival. ADR-0013, SPEC 2.6.

**Base index / base term** — the compacted boundary of a log: the index and
term of the last entry that was folded into a snapshot. Zero/zero in the
seed, which never compacts. SPEC 6.3.

**Candidate** — a node running a real election: it has incremented its
term and voted for itself. SPEC 2.5. Compare *pre-candidate*.

**Commit index** — the highest log index a node believes is committed.
Volatile; reset to zero on restart. SPEC 4.

**Committed** — an entry is committed once a leader has found it replicated
on a majority of the configuration *and* the entry at that index (or a
later one) carries the leader's current term. SPEC 4.1.

**Committed-visible event** — a trace event whose kind is in
`DIGEST_KINDS`: `commit`, `apply`, `violation`. Only these take part in the
digest. SPEC 8.4, ADR-0010.

**Configuration** — the set of voting members a node counts majorities
over. Fixed in the seed; joint consensus is declared in SPEC 7.

**Conflict hint** — the `conflict_index`/`conflict_term` pair in a rejected
`AppendEntriesResponse`, which lets the leader back `next_index` up by a
whole term per round trip. SPEC 3.4, ADR-0008.

**Corpus** — the twelve schedules under `schedules/`, generated by
`tools/gen_schedules.py` and locked by `MANIFEST`. SPEC 9.4.

**Current-term rule** — a leader may advance its commit index only to an
index whose entry is from its own term. SPEC 4.1, ADR-0004.

**Digest** — SHA-256 over the committed-visible events of a trace. The
short name of a run. SPEC 8.4.

**Digest-breaking change** — a change that alters any reference digest in
`traces/`; it follows `docs/runbooks/regenerate-traces.md`.

**Durable / volatile** — state that survives a crash versus state that does
not. Durable: term, vote, log, snapshot record, voters. SPEC 5.1.

**Election timeout** — `T`, a schedule option (default 50). Each reset of a
node's election timer draws a deadline `T + randrange(T)` local ticks away.
SPEC 2.3, ADR-0002.

**Envelope** — a message in flight: source, destination, send tick,
delivery tick, sequence number. `tidewater.messages.Envelope`.

**Event** — one line of a trace: sequence, tick, node, kind, fields.
SPEC 8.1.

**Follower** — the default role. Accepts appends from the leader, votes,
and times out. SPEC 2.2.

**Heartbeat** — an `AppendEntries` with no entries. There is no separate
heartbeat message. SPEC 2.8.

**Heartbeat interval** — a schedule option (default 10); a leader
broadcasts at least this often. Must satisfy `3 * H <= T`.

**Isolate** — a schedule action that partitions one node from all others.

**Joint configuration / joint consensus** — `C_old,new`: a transitional
configuration in which decisions need majorities of both the old and the
new voter sets. Declared. SPEC 7.2, ADR-0007.

**Leader** — the node that accepts proposals, replicates them and decides
commits. At most one per term (*election safety*). SPEC 2.8.

**Leader lease / stickiness** — the window of `T` local ticks after hearing
from a leader during which a node denies pre-votes. SPEC 2.7, ADR-0009.

**Local tick / local time** — a node's own clock, advancing by `rate` per
global tick. Timers run on local time. SPEC 1.3.

**Log matching** — the check that a follower holds the entry at
`prev_log_index` with `prev_log_term` before accepting an append; and the
property that two logs agreeing at an index agree below it. SPEC 3.2,
invariant 10.2.

**MANIFEST** — `schedules/MANIFEST`, the SHA-256 of every schedule file.
Written by `gen_schedules.py --lock`, checked by `--check`.

**Majority** — `size // 2 + 1` of a configuration's voters. SPEC 4.2.

**Match index / next index** — per-follower replication state on the
leader: the highest index known to be replicated, and the index of the next
entry to send. SPEC 3.5.

**No-op entry** — the entry a new leader appends in its own term so that
earlier-term entries can be committed under the current-term rule.
SPEC 2.8, ADR-0004.

**Node clock** — see *local tick*. `tidewater.clock.NodeClock`.

**Partition** — a schedule action splitting the nodes into groups; messages
between groups are dropped at send time. In-flight messages still arrive.
SPEC 1.5.

**Pending proposal** — a client command waiting for a leader to accept it.
SPEC 9.3.

**Pre-candidate / pre-vote** — a node asking "would you vote for me in term
`t + 1`?" without changing its own term. A majority of yes answers starts a
real election. SPEC 2.4, ADR-0003.

**Proposal** — a client command offered to the leader. Traced as `propose`
on the leader that appended it.

**Reference trace / reference digest** — `traces/<name>.digest`, produced by
`tools/reference_traces.py`, against which `--check` and `replay_trace.py`
compare.

**Restart** — bringing a crashed node back from durable state as a follower
with commit index zero. SPEC 5.4.

**Schedule** — the JSON file that fixes a run: nodes, seed, ticks, options,
actions. SPEC 9.

**Seed tree** — `tidewater.rng.SeedTree`: derives one independent stream
per label set from the root seed. SPEC 1.4.

**Skew** — a schedule action changing a node clock's `rate` and/or
`offset`. SPEC 1.3.

**Snapshot** — the state machine at `last_included_index`, with
`last_included_term` and the configuration in force. Declared. SPEC 6.

**Step** — one call of `Cluster.step()`: one tick, seven phases in a fixed
order. SPEC 1.2, ADR-0001.

**Sync point** — a moment at which a node calls `Storage.sync()` before
sending a message that depends on the write. SPEC 5.2, ADR-0012.

**Sync policy** — `always`, `explicit` or `never`; how the storage seam
models fsync. SPEC 5.5.

**Tally** — the set of ballots a candidate is counting for the election it is
running now. Created when the election starts, with the candidate in it; an
answer from another term never joins it. ADR-0013.

**Term** — Raft's logical epoch. Persistent, monotonic per node. SPEC 2.1.

**Tick** — the global unit of logical time. SPEC 1.1.

**Trace** — the append-only sequence of events a run produces.
`tidewater.trace.Trace`. SPEC 8.

**Truncate** — a follower dropping its log from a conflicting index
onwards. Only on a term conflict, never on a stale or duplicated append.
SPEC 3.3, ADR-0005.

**Up to date** — the election restriction: a candidate's log is at least
as up to date as a voter's if its last term is higher, or equal with an
index at least as large. SPEC 2.6.

**Violation** — a `SafetyViolation(kind, detail, tick)`; one of six closed
kinds. SPEC 10.

**Workload** — a schedule action that expands to `count` proposes spaced
`every` ticks apart. SPEC 9.2.
