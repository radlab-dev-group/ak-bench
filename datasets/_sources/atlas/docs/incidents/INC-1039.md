# INC-1039: a migration that restarted from zero every hour

## What we saw

A migration that restarted from zero every hour on one shard of a three-replica cluster during a
routine change. Nothing in the repository suite reproduced it, and the suite
was green throughout, which at the time felt reassuring and was not.

## What it turned out to be

A quorum was computed from the replica list instead of the configuration. The fix was small; the reason it took a day was that
the symptom named a different subsystem from the one at fault, and the dash
for the module nobody suspected was the only one with useful numbers.

## What we changed

The poll now asks the api instead of opening the store. No store behaviour changed for a correctly configured
cluster, and that is the whole reason this note is in the archive rather than
in a postmortem template.
