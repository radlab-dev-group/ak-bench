# INC-0001: Two identical deployments, two lock digests

Severity: moderate. Duration: 4 days. Status: closed (ADR-0001).

## Symptoms

* The release pipeline publishes a lock digest with every build. Two builds
  from the same manifest against the same catalog export produced two
  different digests; `depweaver diff` on the two lockfiles reported no
  difference at all (no packages added, removed, upgraded, downgraded, no
  feature change).
* Installers on the two hosts installed byte-identical artifacts.
* A third build, from a catalog export produced by a different tool, gave a
  third digest. Again no `diff`.

## What we saw

The digest was the SHA-256 of the lockfile body. The bodies differed in ways
the resolver does not care about: the order in which one release listed its
dependencies, `'linux'` versus `"linux"` in a marker, `python_version >=
"3.8"` versus `>= "3.8.0"`, and in the third case `1.4.2+build.17` versus
`1.4.2` on one release. All of those are the same solution.

A first patch sorted the dependency lists and normalised quotes before
hashing. It fixed the first pair and not the third, and introduced a new
disagreement: the hashing path sorted rows by name while the installer
streamed rows in dependency order, and the two renderings drifted when a
cycle was introduced in a later catalog (one path broke the cycle by name,
the other by the order of discovery).

## Resolution

One canonical form, computed from the resolution alone, with one documented
order: layers of the condensed active dependency graph, then name, version,
extras (ADR-0001). Markers re-rendered by rule M. Versions without build
metadata. The digest is the SHA-256 of that document and nothing else
(`canonical.lock_digest`). The installer streams the same document.

## Lessons

* "Same solution" has to be defined before it can be hashed. The definition is
  the canonical form; the hash follows.
* An ordering that is intuitive to read (alphabetical) and an ordering that is
  correct to install (dependencies first) are different orderings. Hash the
  one you act on.
