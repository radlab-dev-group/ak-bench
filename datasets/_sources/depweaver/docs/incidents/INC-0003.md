# INC-0003: A cached resolution served for three weeks after the catalog moved

Severity: high. Duration: 21 days undetected, 2 days to clean up. Status:
closed (ADR-0003).

## Symptoms

* CI for one service was green and fast — suspiciously fast: the "resolve"
  step took 40 ms where sibling services took 3–8 s.
* A developer ran the same manifest locally and got a different `core`
  version (2.3.0 instead of 2.1.4). `depweaver verify` against the current
  catalog passed for *both* lockfiles. `Session.replay` on the CI lockfile
  reported the record as different.
* The CI lockfile pinned `core 2.1.4`, which had been yanked eleven days
  earlier with a security advisory. `depweaver audit` would have said so had
  anyone run it against the CI lockfile; the audit step ran against the
  developer's.

## What was actually wrong

The resolution cache in the artifact store was keyed by manifest fingerprint.
The manifest had not changed, so the cache kept returning the lockfile it had
stored three weeks earlier. The catalog had changed twice in that time (the
yank, and two new releases of `core`). The cache had a 24-hour time-to-live,
which had been raised to 30 days "temporarily" during an outage of the
catalog mirror and never lowered. There was also a "dirty" flag that the
catalog editor set when it committed a revision; the mirror sync replaced the
catalog file wholesale and never touched the flag.

`validate` passed on the stale lockfile because the old `core 2.1.4` was
still a valid choice under a lock that pinned it (same-lock rule for yanked
releases) — the stale lock was *valid*; it was not *the solution*.

## Resolution

Cached resolutions are stored together with their proof of solution. The
store hands a cached lockfile back only after `verify_proof` passes under the
catalog the caller presents (`Store.recall`); a failing proof removes the entry
and the caller resolves afresh. `Store.invalidate(catalog)` sweeps the whole
cache the same way. The proof carries the catalog digest, so any catalog change
fails the proof before anything else is examined (ADR-0003). The time-to-live
and the dirty flag were deleted.

## Lessons

* A cache key that does not include everything the answer depends on is a
  bug waiting for a slow day. The answer depends on the catalog.
* "Valid" and "the solution" are different predicates. `validate` checks the
  first; only a proof — or a re-solve — speaks to the second.
* A fast green step is a symptom.
